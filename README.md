# CamSync

このソースのバージョンは **v2.9.1** です。

CamSyncは、防犯カメラの映像に表示されている時刻と端末時刻を比較し、カメラ時計の進み・遅れを秒単位で計算・記録するモバイル向けPWAです。

バックエンド、アカウント、クラウドデータベース、分析サービス、外部ライブラリを使用しない静的Webアプリです。記録はブラウザのIndexedDBに保存され、保存内容を外部へ送信する処理はありません。

**アプリを開く:** [https://yucchiz.github.io/camsync/](https://yucchiz.github.io/camsync/)

## 主な機能

- 端末の現在時刻を固定し、防犯カメラの表示時刻との差を計算
- カメラ時計の「進み」「遅れ」「時刻どおり」を分・秒と総秒数で表示
- 設置場所、閲覧日、映像の抽出期間、立会人、補足情報を記録
- 保存した履歴の閲覧、編集、個別削除（直後なら元に戻せる）、全件削除
- 記録ごとに写真（JPEG・PNG・WebP・HEIC/HEIF）やPDFを端末内に添付し、プレビュー・保存・共有
- 記録を1件ずつMarkdownファイルとして出力・再インポート
- 全履歴を検証用ハッシュ付きJSONとして一括バックアップ・復元
- Markdownインポート時の形式・日時・誤差・文字数検証と重複警告
- 時刻に時間差を加算・減算できる独立した時間電卓
- 入力途中の状態の下書き保存と、次回起動時の復元
- 端末の設定に合わせたライト／ダーク表示
- 初回読み込み後のオフライン利用と、ホーム画面への追加

## 使い方

### カメラ時刻の誤差を計算・保存する

1. 端末の「日付と時刻」を自動設定にします。
2. 「計算」画面を開き、防犯カメラ映像の時計と端末時計を見比べます。
3. 比較したい瞬間に「タップで固定」を押します。
4. その瞬間にカメラへ表示されていた時刻を `HH:MM:SS` の24時間表記で入力します。
5. 「誤差を計算」を押します。
6. 必要に応じて、次の記録情報を入力します。
   - 防犯カメラ設置場所
   - 閲覧日
   - 映像の抽出開始・終了日時
   - 立会人の氏名・年齢
   - カメラ型番や確認状況などの補足
7. 「この記録を保存」を押します。

閲覧日には、基準時刻を固定した日が自動入力されます。抽出期間は実時刻（正しい時刻）で入力します。抽出終了日を省略した場合は開始日と同日として扱います。終了時刻が開始時刻より前の場合は、日を跨いだものとして終了日が翌日に自動設定されます。

- 記録日時には、保存ボタンを押した時刻ではなく、基準時刻を固定した瞬間を記録します。
- 計算後にカメラ時刻を変更すると計算結果は無効になり、「誤差を計算」をやり直すまで保存できません。
- 「固定し直す」は、入力済みの記録情報を残したまま基準時刻だけを取り直します。「リセット」は入力をすべて破棄します。
- 固定後の入力途中の状態は端末内（`localStorage`）に下書きとして保存され、アプリが閉じられても次回起動時に復元します。下書きは保存またはリセットで消え、固定から24時間を過ぎたものは破棄します。
- 入力内容に誤りがある場合は、該当する入力欄の下に理由を表示します。

### 記録に写真・PDFを添付する

現場で撮ったカメラ画面の写真や、書類をスキャンしたPDFを記録ごとに添付できます。

1. 保存直後に表示される「添付を追加」を押すか、「記録」画面で記録の「編集」を開きます。
2. 編集画面の「添付ファイル」欄で「写真・PDFを添付」を押し、ファイルを選びます（複数選択可）。
3. 画像は「プレビュー」で確認できます。「保存」で端末へ取り出し、共有に対応した環境では「共有」から共有シートで他のアプリへ渡せます。
4. 不要な添付は「削除」で消せます（確認あり・取り消し不可）。

- 添付できるのはJPEG・PNG・WebP・HEIC/HEIF画像とPDFだけです。拡張子ではなくファイルの中身で判定し、SVGやHTMLなどは受け付けません。
- 上限は1ファイル10 MiB、1記録10件です。複数選んで一部だけ失敗した場合は、成功件数と、追加できなかったファイル名と理由を表示します。
- 添付の追加・削除はその場で保存されます。編集画面の「保存」ボタンは記録情報だけに使います。
- HEIC/HEIFはブラウザによってはプレビューできません。その場合は「保存」または「共有」で取り出して確認してください。
- iPhoneのホーム画面アプリ（PWA）でPDFを開くときは、「共有」から「ファイルに保存」や他のアプリを選ぶ方法を推奨します。

### 時間電卓を使う

「時間電卓」画面では、24時間表記の時刻に時間差を加算または減算できます。日を跨ぐ場合は「翌日」「前日」「N日後」「N日前」のように表示されます。

時間差は最大 `999:59:59` まで入力できます。この機能は保存済みの誤差記録とは連動しない、独立した計算ツールです。

### 記録を管理する

「記録」画面では、保存した記録が新しい順に表示されます。

- 「編集」: 設置場所、閲覧日、抽出期間、立会人、補足を編集
- 「MD出力」: その記録をMarkdownファイルとして保存
- 「MDインポート」: Markdownファイルから記録を追加
- 「全件バックアップ」: 全履歴を1つのJSONファイルとして保存
- 「バックアップ復元」: JSONバックアップを既存履歴へ追加、または全件置換
- 「削除」: その記録と添付ファイルを削除。直後のトーストの「元に戻す」で、約6秒以内なら記録と添付をそのまま戻せます
- 「すべての履歴を削除」: 端末内の記録と添付ファイルを全件削除

「履歴の保存状況」には、最終バックアップの日時と、その後に追加された件数の目安を表示します。未実施の場合や追加がある場合は注意を表示し、全件削除と全件置換の確認文にも同じ状況を表示します。最終バックアップの日時は、この端末で「全件バックアップ」を実行した時点を記録したものです。

基準時刻、カメラ表示時刻、計算済みの誤差は「記録」画面では編集できません。個別削除は「元に戻す」の猶予が過ぎた時点、またはアプリを背面に回した時点で確定します。続けて複数件を削除した場合、「元に戻す」は猶予中の削除をまとめて戻します。全件削除は取り消せないため、必要な記録は事前に全件バックアップしてください。添付のある記録には、履歴に添付件数が表示されます。

## Markdownによる記録の保管・移動

「MD出力」は、記録を `camsync_YYYYMMDD_HHMM.md` という名前のUTF-8テキストファイルとして1件ずつ保存します。出力には次の項目が含まれます。

- 記録日時
- 基準時刻
- カメラ表示時刻
- 誤差
- カメラ設置場所
- 閲覧日
- 抽出日・時間
- 立会人
- 補足

インポートできるファイルは1 MiBまでです。CamSyncが出力したMarkdownファイルの利用を推奨します。手作業で編集する場合は、`- **基準時刻:** 値` のようなラベルと書式を変更しないでください。存在しない日時、計算結果と矛盾する誤差、重複ラベル、上限を超える文字列などは理由を表示して拒否します。

補足が複数行の場合は、2行目以降を半角スペース2つでインデントした継続行として出力し、インポート時に改行を復元します。旧版が出力した ` / ` 区切りの1行の補足は、そのままの文字列として読み込みます。

インポートは既存履歴へ記録を追加します。同一内容の記録がある場合は、追加前に重複を警告します。旧版が出力した同日形式、開始時刻のみ、終了時刻のみのMarkdownも引き続き読み込めます。

## 全件バックアップと復元

全件バックアップは、履歴、形式バージョン、作成日時、アプリバージョン、破損検知用SHA-256を1つのJSONファイルへ保存します。復元時はファイル形式、ハッシュ、件数、各記録、ID重複を追加前に検証します。上限は10 MiB、10,000件です。

「記録」画面には、保存件数と推定バックアップ容量を常時表示します。10,000件または10 MiBの80%に達すると注意を、上限に達するか超えると警告を表示します。これは全件バックアップの上限であり、ブラウザやIndexedDB自体の固定保存上限ではありません。上限に近づいても既存履歴は自動削除されません。

復元方法は次の2種類です。

- 追加: 既存履歴を残し、重複していない記録だけを追加
- 全件置換: 検証に成功したバックアップで現在の履歴を原子的に置換

全件置換は取り消せません。復元前にも現在の全件バックアップを作成してください。

**添付ファイルは全件バックアップとMarkdown出力に含まれません。** 全件置換で復元すると、現在の添付ファイルはすべて削除されます（確認文に件数を表示します）。「追加」での復元では既存の添付は残ります。必要な添付は、記録の編集画面から1件ずつ「保存」または「共有」で取り出して保管してください。添付が1件以上あるときは、「記録」画面にこのことを常時表示します。

## インストールとオフライン利用

CamSyncはインストール可能なPWAです。ブラウザのメニューから「インストール」または「ホーム画面に追加」を選んでください。iPhoneおよびiPadでは、Safariの共有メニューから「ホーム画面に追加」を選択できます。表示名はOSやブラウザによって異なります。

初回アクセス時は、アプリ本体を読み込みキャッシュするためにネットワーク接続が必要です。一度正常に読み込んだ後は、キャッシュを利用してオフラインでも起動できます。起動時やアプリを前面へ戻したときには、オンラインであれば新しいバージョンを確認します。更新が見つかるとアプリ内に案内と主な更新内容を表示し、「更新する」を選んだ時だけ新しいService Workerへ切り替えます。

### iPhoneでv2.9へ更新する

1. 更新前に「記録」画面から「全件バックアップ」を実行します。
2. iPhoneをオンラインにして、ホーム画面のCamSyncを開きます。
3. 更新案内が表示されたら「更新する」を押します。
4. 旧v2.4では案内が出ないことがあります。その場合は、アプリスイッチャーでCamSyncを終了して開き直します。
5. 「記録」画面を開き、従来の設置場所、立会人、抽出期間、補足が残っていることを確認します。

アプリ本体のキャッシュ更新と、記録を保存するIndexedDBは別領域です。v2.9はデータベース名 `CamSyncDB` とストア名 `records` を維持したまま、添付用のストアを追加するためにスキーマバージョンを `2` へ上げます。既存の `records` は変更しないため、通常のPWA更新では既存履歴を削除しません。v2.9へ更新した後に旧バージョンへ戻すと、データベースを開けなくなります。更新のためにSafariの「履歴とWebサイトデータを消去」やサイトデータ削除を行わないでください。

## データ保存とプライバシー

記録は、利用中のブラウザのIndexedDB（`CamSyncDB`）に保存されます。サーバーへの保存、アカウント連携、クラウド同期、分析は行わず、保存した記録を外部送信する処理もありません。

次の点に注意してください。

- データは同じブラウザ、同じブラウザプロファイル、同じサイト内でのみ利用できます。
- 別の端末やブラウザへ自動では同期されません。
- 通常のアプリ更新では履歴を維持しますが、Safariの履歴・Webサイトデータ削除、ブラウザプロファイルの削除、OSによるサイトデータの消去、端末の初期化などにより失われる可能性があります。
- Markdownファイルには設置場所、日時、立会人、補足などの機微な情報が含まれる場合があります。出力後のファイルも適切に管理してください。
- 添付ファイル（写真・PDF）も同じIndexedDBの端末内にだけ保存され、外部へ送信されません。全件バックアップには含まれないため、端末のサイトデータが消えると添付は戻せません。取り出したファイルも適切に管理してください。
- 端末の保存容量が不足した場合は、容量不足である旨を表示して保存を中止します。

IndexedDBのスキーマバージョンは `2` です。バージョン `1` の `records` ストアはそのまま維持し、添付用に `attachments`（メタ情報）と `attachmentBlobs`（ファイル本体）のストアを追加しています。旧バージョンのCamSyncを別のタブで開いたままにしていると更新できないことがあるため、その場合は他のタブを閉じてから再読み込みしてください。

記録を保存すると、ブラウザに保存領域の永続化（`navigator.storage.persist()`）を要求します。許可されるかどうかはブラウザが判断します。現在の状態と使用量の目安は「情報」画面の「保存領域」で確認できます。

入力途中の下書きと最終バックアップの日時は、同じブラウザの `localStorage` に保存します。これらも外部へ送信しません。

重要な記録は、定期的に全件バックアップし、別の安全な場所へ保管することを推奨します。

## 計算仕様と注意事項

- 基準時刻には、CamSyncを開いている端末の時計を使用します。CamSync自体が時刻サーバーと同期したり、端末時計の正確性を検証したりする機能はありません。
- 端末時計が手動設定の場合、計算精度は保証されません。OSの「日付と時刻」は自動設定を推奨します。
- 誤差は基準時刻とカメラ表示時刻の24時間内の差から、日付境界を考慮して±12時間の範囲で算出します。12時間を超える実際のずれや、日数単位のずれを測定する用途には適していません。
- 本アプリは時刻差の計算と記録を補助するツールです。記録の正確性は、比較時の操作、端末時計、入力内容に依存します。

## ローカルで実行する

依存関係のインストールやビルドは不要です。

```sh
git clone https://github.com/yucchiz/camsync.git
cd camsync
python3 -m http.server 8000
```

ブラウザで [http://localhost:8000/](http://localhost:8000/) を開きます。IndexedDBとService Workerを本番に近い条件で動かすため、`index.html`を`file://`で直接開かず、HTTPで配信してください。

### ファイル構成

```text
.
├── index.html         # セマンティックな画面構造
├── styles.css        # レスポンシブ表示とアクセシビリティ
├── app.mjs           # DOM連携と画面制御
├── lib/
│   ├── time.mjs      # 誤差・時間電卓・抽出期間の純粋関数
│   ├── record.mjs    # 記録の正規化と検証
│   ├── markdown.mjs  # Markdown入出力
│   ├── storage.mjs   # IndexedDB操作（記録・添付・削除の取り消し猶予）
│   ├── attachment.mjs # 添付ファイルの種類判定・サイズ／件数・ファイル名の検証
│   ├── backup.mjs    # 全件バックアップ・復元検証
│   ├── backup-status.mjs # 最終バックアップの日時・件数と表示文
│   ├── draft.mjs     # 計算画面の下書きの直列化と検証
│   ├── form-errors.mjs # 検証エラーの入力欄への振り分け
│   ├── storage-info.mjs # 永続化の状態と使用量の表示文
│   ├── release-notes.mjs # 更新案内に表示する更新内容の整形
│   ├── safe-storage.mjs # localStorageを例外なしで扱う補助
│   └── viewport.mjs  # iOSキーボード表示後のviewport補正
├── test/             # Node標準テストと旧形式fixture
├── manifest.json     # PWAメタデータ
├── sw.js             # キャッシュ更新とオフライン動作
└── icons/            # SVG、PNG、maskable、Apple用アイコン
```

## 開発時の確認

自動テストと静的チェック:

```sh
node --test test/*.test.mjs
node --check app.mjs
node --check sw.js
for f in lib/*.mjs; do node --check "$f"; done
python3 -m json.tool manifest.json >/dev/null
git diff --check
```

変更時には自動テストに加え、モバイル幅のブラウザで次の項目を確認してください。

- 誤差計算と日付境界付近の計算
- 保存、編集、削除、再読み込み後のIndexedDB永続化
- 現行形式のMarkdown出力と、旧形式・現行形式のインポート
- 初回読み込み後のオフライン起動とキャッシュ更新
- 保存記録から独立した時間電卓の計算
- 添付の追加（複数・一部失敗・上限）、プレビュー、保存・共有、削除、削除の取り消しで添付が残ること

`sw.js`やキャッシュ対象を変更した場合は、`CACHE_NAME`を一度だけ更新し、旧版を登録した同一オリジンから通常の更新操作で確認してください。検証中にサイトデータを消すとIndexedDB保持を確認できないため、更新試験では消去しないでください。
